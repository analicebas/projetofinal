Vamos montar o projeto do zero!
A ideia é desenvolver um site para facilitar a participação dos alunos no Grand Prix do SENAI, organizando as demandas, os prazos e o envio das propostas em um só lugar.

Minha sugestão é criar um site com aparência de plataforma profissional de tecnologia e inovação, com uma identidade visual inspirada em automobilismo, velocidade e competição, mas sem ficar exagerada.

Vamos organizar o projeto em etapas para que vocês consigam desenvolver, apresentar e explicar o sistema ao professor.
1. 💡 Como será o site?
O sistema terá três perfis principais:
Perfil	O que poderá fazer
🎓 Aluno	Visualizar demandas da própria unidade, consultar requisitos, enviar propostas e acompanhar o andamento.
👨‍🏫 Professor	Consultar demandas, acompanhar as propostas dos alunos e visualizar atualizações relacionadas à participação.
🛠️ Organização	Cadastrar unidades, eventos e demandas, definir prazos, consultar propostas e gerenciar o sistema.


Cada perfil terá acesso às funcionalidades necessárias para suas atividades.
Principais páginas
Área pública e acesso
- Página inicial com apresentação do Grand Prix.
- Página de login.
- Página de cadastro.
- Recuperação de senha.
Área do aluno
- Painel inicial com resumo das atividades.
- Demandas disponíveis para sua unidade.
- Detalhes da demanda e requisitos de entrega.
- Formulário para envio de propostas.
- Minhas propostas e respectivos status.
- Calendário de prazos.
- Central de notificações.
Área do professor
- Painel para acompanhar os alunos e as propostas.
- Consulta às demandas.
- Visualização dos prazos e das atualizações.
Área da organização
- Gerenciamento de usuários e perfis.
- Cadastro de unidades e eventos.
- Cadastro, edição e encerramento de demandas.
- Configuração dos requisitos de entrega.
- Gerenciamento dos prazos.
- Consulta e gerenciamento das propostas.
- Histórico das edições do Grand Prix.
Uma parte importante do projeto será permitir que o aluno veja os requisitos de uma demanda antes de começar a elaborar e enviar sua proposta.

7. 🗄️ Como organizar o banco de dados
O banco de dados será uma parte essencial do projeto.

Sugiro começar com estas tabelas:
Tabela	O que armazenará
usuarios	Nome, e-mail, senha protegida, perfil e unidade.
unidades	Identificação das unidades do SENAI.
eventos	Edições e informações dos eventos Grand Prix.
demandas	Descrição, unidade, evento, requisitos e prazos.
propostas	Arquivos enviados, aluno responsável, data e status.
etapas	Etapas da competição e respectivas datas-limite.
notificacoes	Avisos destinados aos usuários.
historico_status	Mudanças de situação das propostas.


As tabelas deverão estar relacionadas para que o sistema consiga, por exemplo, identificar quais demandas pertencem a determinada unidade e quais propostas foram enviadas para cada demanda.
Exemplo de funcionamento
1. A organização cadastra uma demanda para determinada unidade.
2. O aluno entra no sistema.
3. O sistema identifica a unidade vinculada à conta dele.
4. As demandas são filtradas de acordo com essa unidade e as regras de participação do evento.
5. O aluno abre uma demanda e consulta os requisitos, o formato de entrega e o prazo.
6. O aluno envia sua proposta.
7. O sistema valida o arquivo no servidor e registra a proposta.
8. O aluno acompanha o status no painel pessoal.
Assim, resolvemos o principal problema descrito no escopo do projeto.

9. 🚀 Ordem de desenvolvimento
Para não ficar confuso, sugiro seguir esta sequência:

Etapa 1 — Preparação
- Criar a pasta do projeto.
- Configurar o repositório no GitHub.
- Criar a estrutura básica de arquivos.
- Definir a paleta de cores e os componentes visuais.
Etapa 2 — Interface
- Criar a página inicial.
- Desenvolver o login e o cadastro.
- Criar o painel do aluno.
- Desenvolver a listagem e os detalhes das demandas.
Etapa 3 — Banco de dados e back-end
- Criar o banco MySQL.
- Implementar cadastro e autenticação.
- Configurar os perfis e as permissões.
- Implementar a filtragem das demandas por unidade.
Etapa 4 — Propostas
- Criar o formulário de envio.
- Validar os formatos e tamanhos dos arquivos no servidor.
- Registrar as propostas.
- Implementar o acompanhamento de status.
Etapa 5 — Administração
- Criar o painel da organização.
- Implementar o gerenciamento de demandas e prazos.
- Desenvolver o histórico e as notificações.
Etapa 6 — Finalização
- Testar o sistema com os três perfis.
- Verificar a responsividade.
- Corrigir erros e revisar a segurança.
- Preparar a documentação técnica e o manual do usuário.
